# Task 12：L1 Memory System 与完整周期模拟器闭合

在 Task11 已完成的 Multi-Warp Core、CTA/Kernel 执行闭环基础上，以冻结 RTL 和 Timing IR 为主要依据，补齐 Core 到外部 memory 之间的存储层级，完成当前冻结配置下周期模拟器的完整构建。

本阶段重点是实现 L1 级存储行为、访存请求组织和真实的存储资源竞争，使 Fetch、LSU、LMEM 与 Kernel execution 不再依赖简单的固定延迟 memory service。

## 主要内容

建立冻结配置下的完整访存路径：

```text
Fetch
  ↓
L1 I-Cache
  ↓
External Memory Backend

LSU
  ↓
Local / Global 路由
  ├─ Local Memory
  └─ Memory Coalescing
        ↓
      L1 D-Cache
        ↓
External Memory Backend
```

根据 RTL 实现当前配置实际启用的 I-cache、D-cache 和 local memory 行为。

L1 Cache 至少应表达命中与缺失路径、bank/port 资源、请求队列、MSHR、replacement、refill、store/update、writeback 和相应 backpressure，使 Cache 状态和资源占用真实影响 Fetch 与 LSU 的推进。具体容量、路数、延迟和结构从冻结配置及 RTL 获取，不另建经验参数表。

实现 SIMD lane 访存请求的合并与返回拆分，根据 RTL 确定地址分组、byte enable、请求覆盖、响应 mask 和冲突关系。访存合并属于实际 LSU→memory 路径的一部分，不能继续由功能 memory service 一次性完成整组 lane 访问。

Local memory 保留已有功能地址和数据语义，并补充当前 RTL 实际存在的 bank、端口、冲突和响应时序，使 LMEM 与 global memory 经过各自正确的周期路径。

## 外部 Memory 边界

L1 之外不实现真实 DRAM 微架构。

建立简单、确定的外部 memory backend，为 I-cache/D-cache miss、refill 和必要的 writeback 提供请求与响应接口。外部访问可以采用固定延迟模型，例如：

```text
External Memory Latency = 100 cycles
```

该延迟作为显式模拟参数存在，仅代表 L1 以下未建模存储系统的统一服务时间，不模拟 DRAM channel、bank、row buffer、queue 或 controller。

外部 backing memory 继续保存最终可观察的数据，但需要根据当前 Cache 策略正确处理 cache line、dirty data 和 writeback 的可见关系，不能在采用 writeback Cache 时仍让所有 store 无条件立即修改 backing memory。

## Kernel 与完成条件

将 Task11 的 Kernel execution 接入新的 I-cache、D-cache、LMEM 和访存合并路径，使完整 Kernel 的 instruction fetch、global load/store 和 local memory 都经过周期存储系统。

Kernel 完成判断应考虑尚未完成的 Cache request、miss/refill、writeback、LSU response 和其它必要的 memory work，避免在 Warp/CTA 已结束但存储系统仍存在有效工作时提前结束。

最终结果的读取方式和必要的 Cache 可见性操作应依据 RTL 路径确定，不默认通过清空整个 Cache 来规避状态一致性问题。

## 约束边界

本阶段不实现：

* DRAM controller 及 DRAM 内部时序；
* L2 / L3 Cache；
* 多 Core Cache coherence；
* VM / TLB / page-table timing；
* host runtime；
* RTLSIM trace 精度收敛。

不重新实现 Task9–Task11 已经完成的 Scheduler、Scoreboard、执行流水和 Kernel orchestration。若新的 memory backpressure 暴露已有控制边界错误，应修正对应接口和 Timing IR，而不是绕开真实阻塞关系。

继续保持功能结果与周期资源解耦：功能语义决定访问什么地址、读写什么数据；周期模型决定请求如何合并、经过哪些存储资源、等待多久以及何时返回。

## 完成标准

完成后，周期模拟器能够使用同一个 Kernel 入口执行完整 Kernel，并实际经过：

**Multi-Warp Pipeline → LSU/Fetch → Coalescing/LMEM → L1 I/D Cache → Fixed-Latency Memory Backend**

Cache hit、miss、MSHR 占用、访存合并、bank/port 冲突、refill、writeback 和外部 memory latency 均能影响实际执行周期和 Warp stall。

在不同 Cache 行为、访存冲突和外部固定延迟条件下，最终架构状态与 Kernel 输出保持功能正确。

Task12 最终交付的是 **冻结单 Core 配置下功能完整、存储层级完整、可以执行完整 Kernel 的周期级 Vortex 模拟器**。
