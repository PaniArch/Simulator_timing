先读取并遵守现有 `docs/architecture.md`，在 T1–T6 已完成的 ISA、Warp、Multi-Warp Core、CTA 和 Barrier 基础上完成 **T7：Kernel Functional Execution**。

本阶段是功能模拟器主体的最后一层，目标是建立稳定的 Kernel 级执行入口：给定冻结配置下的 Kernel launch state 和已经装入程序、参数及输入数据的 memory，模拟器能够从 Kernel 启动一直执行到整个 Kernel 完成，并在同一 memory 中得到最终结果。

### 上层接口

建立一个与具体 runtime 解耦的 Kernel launch 接口。Launch state 应根据冻结 RTL 中 KMU 实际消费的状态确定，至少覆盖：

* startup PC；
* kernel entry PC；
* kernel parameter address；
* grid dimensions；
* block dimensions；
* block size；
* warp step；
* local memory size；
* 当前冻结路径实际需要的其它 CTA/launch 参数。

注意区分 startup PC 与 kernel entry PC：Warp 按 RTL 从 startup PC 开始执行，kernel entry 作为 CTA context 传入，不要直接跳过 Kernel startup/prologue。

Kernel arguments 以已经存在于 device memory 中的参数地址传入。T7 不解释 host-side argument struct，也不在执行器内部重新 staging 参数。

### Memory 边界

继续复用现有 `InstructionSource`、`MemoryService` 和 `support/memory` 设计，但 T7 顶层必须允许外部提供 backing memory。

Kernel image、kernel arguments、global input/output data 和指令 fetch 应能够来自同一 canonical backing store，不在 T7 中创建或维护第二份 program/data memory。

`support/memory` 继续作为 standalone 测试使用的默认功能后端；不要在 T7 中加入 cache、DRAM timing、MMU 或新的 memory architecture。

CTA local memory 继续由 T6 已建立的 CTA/Core 层负责，不与外部 global backing memory 混合。

### 主要实现

1. 建立 Kernel/Device 级执行入口，接受 Kernel launch state 和现有 memory/interface，初始化本次 Kernel 的瞬态执行状态，但不清空外部 global memory。

2. 根据 `VX_kmu` 和现有 Architecture Contract 实现冻结配置下的功能级 Kernel/CTA 生成过程：

   * 从 grid 产生 CTA；
   * 维护 block index；
   * 生成 T6 CTA 层所需的 launch context；
   * 在 CTA/Core 可以接受新工作时继续推进；
   * grid 完成后停止生成新的 CTA。

3. 不在 T7 重写 CTA、Warp 或 Lane 初始化。将 startup PC、entry、param、grid/block 等 context 传给已有 T6/T5 层，由现有 CTA → Warp → Lane 路径完成：

   * Warp 分配；
   * thread mask；
   * thread/warp/CTA context；
   * LMEM ownership；
   * `mscratch` / CTA CSR 初始化；
   * Warp lifecycle。

4. 建立完整 Kernel execution loop，持续推进：

   `Kernel/KMU → CTA → Core scheduler → Warp → Fetch/Decode/ISA/Commit → Barrier/Memory`

   直到 grid 已经全部发出，并且所有已创建 CTA、Warp 和当前功能执行状态全部完成。

5. Kernel completion 不能只依据 grid/CTA generation 是否结束。只有不存在后续 CTA、resident CTA、active/blocked Warp 或尚未完成的功能 effect/memory operation 时，Kernel 才能报告完成。

6. Kernel 完成后不复制或重建一份结果 memory。最终 global output 保留在传入的 backing memory 中，由调用者直接读取；测试可以使用现有 Snapshot/Read 能力检查结果。

7. 扩展 trace 和测试，验证：

   * startup PC 与 kernel entry 正确区分；
   * parameter address 能正确传入真实执行路径；
   * grid 能产生多个 CTA 并连续执行；
   * CTA/Warp 复用现有 T1–T6 状态和语义；
   * partial Warp/thread context 正确；
   * 多个 CTA 完成后仍能继续执行剩余 CTA；
   * Kernel 不会提前 completion；
   * Kernel 结束后的 global memory 与预期功能结果一致。

### 本阶段不实现

* Vortex host runtime；
* Command Processor / command queue；
* `vx_*` API；
* `.vxbin` module/kernel symbol 解析；
* host-side buffer allocation；
* runtime args staging；
* runtime DCR/CP transport ABI；
* cgo/runtime backend；
* cache、DRAM timing、pipeline timing 或性能模型；
* 冻结配置范围之外的新体系结构功能。

这些属于 T7 完成后的 Runtime Integration，只允许通过 adapter 将 Vortex runtime 已准备好的 launch state 和 canonical device memory 接入 T7，不属于功能模拟器主体。

整个过程中持续维护 `docs/architecture.md`。T7 重点冻结以下最终边界：

* Runtime 与 Kernel execution 的职责边界；
* Kernel launch state；
* startup PC 与 kernel entry ownership；
* parameter ownership；
* global memory ownership；
* Kernel → CTA → Warp 的层级关系；
* Kernel completion 条件。

不得为了完成 T7 重新实现或绕开 T1–T6 已经完成的 ISA、Warp、Core、CTA、Barrier 和 memory semantics；发现上层接口无法自然接入现有层时，应优先修正顶层 orchestration/interface，并同步更新 Architecture Contract。

完成后运行项目现有完整验证，并保持 T1–T6 原有测试通过。

**T7 完成标准：**

* 模拟器具有稳定的 Kernel-level execution entry；
* 能从 startup PC 正确进入真实 Kernel 执行路径；
* kernel entry 和 parameter address 能通过已有 CTA/Warp context 正确生效；
* 能根据 grid/block launch state 连续产生和执行多个 CTA；
* 所有 CTA/Warp 都通过已有 T1–T6 路径执行，不存在第二套 Kernel 专用执行逻辑；
* instruction fetch、global load/store、kernel image、args 和 output 可以共享外部提供的 canonical backing memory；
* Kernel completion 不会在 CTA 或 memory work 尚未完成时提前发生；
* Kernel 完成后最终 global memory/output 可直接读取；
* Architecture Contract 与最终 Kernel execution 实现保持一致；
* 项目完整验证通过。

T7 最终交付的是 **一个与 host runtime 解耦、能够接收硬件可见 Kernel launch state 和外部 device memory，并完整执行 Vortex Kernel 到结束的功能执行引擎**。

T7 完成后，后续只需单独实现 Vortex Runtime / Command Processor → T7 的 adapter，不再修改模拟器已有 ISA、Warp、Core、CTA 和 Barrier 架构。
